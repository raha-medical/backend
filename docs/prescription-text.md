# الوصفة النصية الواحدة

ترحيل إضافي `031_prescription_text.sql` يضيف `prescriptions.text` دون حذف الأسطر القديمة. حد الإدخال في API هو 10,000 حرف. تُحفظ فواصل الأسطر دون تقسيم النص إلى علاجات أو استنتاج جرعات منه، مع إزالة الفراغات الطرفية فقط.

`POST /consultations` و`PATCH /consultations/{id}` يقبلان `prescription_text` اختيارياً، مع بقاء `prescription` القديم مدعوماً. لا يقبل الطلب نصاً وقائمة أدوية غير فارغة معاً. في PATCH، غياب الحقل يبقي الوصفة، والنص الفارغ يمحو الوصفة غير المسعرة. النص المتغير لوصفة مسعرة أو مصروفة يُرفض بـ409 `PRESCRIPTION_LOCKED`. تبقى صلاحية الطبيب وملكية المعاينة ونافذة التعديل الحالية.

ردود المعاينة والسجل والزيارة تضيف `prescription.text`، وردود الصيدلية وتطبيق المريض تضيف `text`. الأسطر القديمة تبقى في `lines`/`items` دون تغيير. واجهة الطبيب تعرض النص أو تنسيق الأسطر القديمة، ولا تحول القديمة عند حفظ تشخيص دون تعديل الوصفة. العرض والطباعة يستخدمان النص كبيانات، مع الهروب من HTML عند الطباعة.

الصيدلي يقرأ النص كما كتبه الطبيب، ويضيف بنود صرف من كتالوج فرعه يدوياً. أول `POST /pharmacy/prescriptions/{id}/bill` لوصفة نصية غير مسعرة يقبل 1–30 بنداً بأرقام متتالية، وكل بند يحتاج `service_id` من كتالوج الصيدلية؛ لا يوجد تحليل آلي للنص. تُنشأ `prescription_lines` من اختيارات الصيدلي داخل معاملة التسعير الحالية، دون تغيير نص الطبيب. تبقى حدود الكمية والأسعار والعملة ومسارات الدفع والصرف القديمة.

يُرفض الصرف الفارغ قبل التسعير بـ422 `PRESCRIPTION_NOT_BILLED`، والصرف قبل الدفع بـ402، وإعادة الصرف بـ409. لا مخزون جديد ولا صلاحيات إضافية.
